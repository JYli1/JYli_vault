# AWDP 实战策略与技巧

## 一、比赛时间分配策略

### 典型 4-6 小时赛程分配

```
0:00 - 0:15  环境检查 + 下载所有题目 + VPN 连接
0:15 - 0:30  快速浏览所有题目，按难度排序
0:30 - 2:00  主攻最有把握的题（Break + Fix 一起做）
2:00 - 3:30  攻克第二道题
3:30 - 5:00  尝试剩余题目
5:00 - 5:30  检查所有 Fix 是否提交成功，查漏补缺
最后 30 分钟  不要再开新题，专注优化已有 Fix
```

### 核心原则
- **先 Break 再 Fix** — Break 找到漏洞后，Fix 就是反向操作，效率最高
- **先易后难** — 拿稳基础分比冲难题更重要
- **Fix 不要拖** — 做完 Break 立刻 Fix，不要攒到最后

## 二、拿到题目后的 30 秒速判

### Web 题速判流程

```
看到源码
  │
  ├─ PHP？
  │   ├─ 搜 unserialize → 反序列化
  │   ├─ 搜 eval/system/exec → 命令注入
  │   ├─ 搜 include/require → 文件包含
  │   ├─ 搜 $_GET/$_POST 拼接 SQL → SQL 注入
  │   ├─ 搜 move_uploaded_file → 文件上传
  │   └─ 搜 curl/file_get_contents → SSRF
  │
  ├─ Python Flask？
  │   ├─ 搜 render_template_string → SSTI
  │   ├─ 搜 os.system/subprocess → 命令注入
  │   ├─ 搜 pickle.loads → 反序列化
  │   └─ 搜 f-string 拼接 SQL → SQL 注入
  │
  └─ Java？
      ├─ 搜 ObjectInputStream → 反序列化
      ├─ 搜 Runtime.exec → 命令注入
      ├─ 搜 JNDI/lookup → JNDI 注入
      └─ 搜 SpEL/OGNL → 表达式注入
```

### Pwn 题速判流程

```
checksec 结果
  │
  ├─ 无 Canary + 无 PIE → 大概率栈溢出，最简单
  ├─ 有 Canary → 找格式化字符串泄露 canary
  ├─ 有 PIE → 需要先泄露地址
  └─ 有堆操作 → 堆题（UAF/Double Free/溢出）

IDA 反编译
  │
  ├─ 看到 gets/scanf("%s") → 栈溢出
  ├─ 看到 printf(buf) → 格式化字符串
  ├─ 看到 malloc/free 菜单 → 堆利用
  └─ 看到 system("cat flag") → 后门函数，ret2text
```

## 三、快速搜索危险函数的命令

```bash
# PHP — 一键搜所有危险函数
grep -rn "eval\|system\|exec\|passthru\|shell_exec\|popen\|unserialize\|include\|require\|file_get_contents\|curl_exec\|assert\|preg_replace.*\/e" src/

# Python
grep -rn "os\.system\|os\.popen\|subprocess\|eval\|exec\|pickle\|render_template_string\|__import__" src/

# Java
grep -rn "Runtime\.exec\|ProcessBuilder\|ObjectInputStream\|readObject\|lookup\|SpelExpression\|OGNL" src/

# 搜 flag 关键字
grep -rn "flag\|FLAG\|secret\|key" src/

# 搜数据库操作（找 SQL 注入）
grep -rn "SELECT\|INSERT\|UPDATE\|DELETE\|query\|execute" src/
```

## 四、团队分工建议

### 两人队

```
队员 A（Web 选手）：
  - 负责所有 Web 题的 Break 和 Fix
  - 熟悉 PHP/Python/Java 审计
  - 工具：Burp Suite + sqlmap + 蚁剑

队员 B（Pwn 选手）：
  - 负责所有 Pwn 题的 Break 和 Fix
  - 熟悉二进制逆向和利用
  - 工具：IDA + pwntools + GDB
```

### 三人队

```
队员 A：Web Break（攻击）
队员 B：Pwn Break（攻击）
队员 C：全部 Fix（防御）+ 辅助

C 的角色很关键：
- A/B 做出 Break 后，立刻告诉 C 漏洞点
- C 负责修复 + 打包 + 提交
- 这样 A/B 可以不间断地攻击下一题
```

## 五、Fix 的实战技巧

### 5.1 万能 Web 修复思路

```
1. 找到漏洞函数/代码行
2. 判断漏洞类型
3. 用最小改动修复：
   - SQL 注入 → 加 intval() 或 预处理语句
   - 命令注入 → escapeshellarg() 或 白名单
   - 文件上传 → 白名单后缀 + 重命名
   - SSTI → 用模板变量替代字符串拼接
   - 反序列化 → 换 json_decode
   - 文件包含 → 白名单 或 basename()
4. 本地测试正常功能
5. 打包上传
```

### 5.2 Fix 失败排查

```
提交后显示"修复失败"？

检查清单：
□ 打包格式对不对？（tar.gz，路径层级）
□ 文件名改了没有？（不能改）
□ 正常功能还能用吗？（最常见的失败原因）
□ 漏洞真的堵住了吗？（可能有多个漏洞点）
□ 文件编码对不对？（UTF-8，LF 换行）
□ 是不是改多了？（只改必要的地方）
```

### 5.3 快速验证 Fix 是否有效

```bash
# Web：本地起服务测试
cd src/
php -S 0.0.0.0:8080    # PHP
python3 app.py          # Python Flask
node server.js          # Node.js

# 然后用自己的 exp 打一下，看是否还能打通
# 再测试正常功能（登录、查询等）

# Pwn：本地运行测试
chmod +x pwn1_patched
./pwn1_patched
# 输入正常数据看是否正常
# 用自己的 exp 打一下看是否还能打通
```

## 六、常见坑与应对

### 坑 1：VPN 连不上
```
- 提前测试 VPN 客户端
- 准备备用网络（手机热点）
- 记住赛方技术支持联系方式
```

### 坑 2：题目环境有问题
```
- 先确认是不是自己的问题（网络、payload 格式）
- 和其他队伍确认是否也有问题
- 及时联系裁判
```

### 坑 3：Flag 格式不对
```
- 仔细看比赛公告中的 flag 格式
- 常见格式：flag{xxx}、FLAG{xxx}、ctf{xxx}
- 有些平台 flag 是动态的，每次请求不同
- 注意 flag 中有没有换行符或空格
```

### 坑 4：Fix 反复失败
```
- 可能有多个漏洞，你只修了一个
- 可能修复方式太激进，破坏了正常功能
- 试试最小改动原则：只注释/替换漏洞那一行
- 看看是否有隐藏的后门（比如 .bak 文件、隐藏路由）
```

### 坑 5：时间不够
```
- 不要死磕一道题超过 1 小时
- 先把所有能拿的 Fix 分拿了（Fix 通常比 Break 简单）
- 最后 30 分钟不开新题
```

```
□ 网络环境测试通过
□ 队伍分工明确
□ 比赛平台账号登录测试
```

## 八、比赛中的心态管理

```
- 前 30 分钟看不懂题很正常，不要慌
- 一道题卡住了就先换一道
- Fix 分是稳定收入，Break 分是锦上添花
- 和队友保持沟通，避免重复劳动
- 遇到问题先搜索，再问队友，最后问裁判
```
