# AWDP 赛制规则与流程

## 一、什么是 AWDP

AWDP = Attack, Defense, Web and Pwn，是 CTF 线下赛中最常见的攻防赛制之一（也有说法称为 Attack With Defense Plus，不同赛事叫法略有差异）。
与传统 AWD（Attack With Defense）的核心区别在于：**AWDP 不需要维护自己的靶机服务，没有持续的攻防对抗轮次**，而是分为 **Break（攻击）** 和 **Fix（修复）** 两个独立环节。

### AWDP vs AWD 对比

| 对比项 | AWD | AWDP |
|--------|-----|------|
| 靶机 | 每队维护自己的靶机，需要 SSH 登录加固 | 不维护靶机，题目由平台统一提供 |
| 攻击方式 | 用 exp 打其他队的靶机，每轮刷 flag | 类似 CTF 解题，Break 拿 flag |
| 防御方式 | SSH 登录自己靶机修代码、部署 WAF | 修改源码/二进制打包上传（Fix） |
| 轮次 | 有多轮攻防，每轮刷新 flag | 无轮次概念，一次性提交 |
| 实时性 | 需要持续监控和防御 | 做完提交即可 |
| 难度侧重 | 运维能力 + 攻击能力 | 纯漏洞审计 + 修补能力 |

简单理解：
- **Break** = 做 CTF 题，找到漏洞拿到 flag
- **Fix** = 修补漏洞，让官方的自动化 checker 打不通你的修复版本

## 二、题目类型

AWDP 通常只有两大类题目：

| 类型 | 说明 |
|------|------|
| **Web** | PHP / Python / Java / Node.js 等 Web 应用，常见漏洞：SQL注入、命令注入、文件上传、反序列化、SSTI 等 |
| **Pwn** | C/C++ 二进制程序，常见漏洞：栈溢出、格式化字符串、堆利用、UAF 等 |

每道题同时有 Break 和 Fix 两个提交入口。

## 三、得分机制

### Break 得分
- 找到漏洞，获取 flag，提交到平台
- flag 格式通常为 `flag{xxxx}` 或平台指定格式
- **每道题的 Break 分值固定**，先做出来不一定加分（不同于 Jeopardy 的动态分值）
- 有些比赛 Break 采用"血量"机制：攻破的队伍越多，每队得分越少

### Fix 得分
- 修复漏洞后，将修改过的文件打包为 **tar.gz** 上传
- 平台会用 **自动化 checker** 检测：
  1. **功能性检查**：你的修复不能破坏程序正常功能（否则判定修复失败）
  2. **安全性检查**：官方 exp 打不通你的修复版本（否则判定修复失败）
- 两项都通过才算 Fix 成功，获得防御分

### 典型分值比例
- Break 和 Fix 通常各占 50%，但不同比赛可能不同
- 有些比赛 Fix 分值更高，鼓励防御能力
- CISCN（国赛）等大型赛事中，Fix 分往往是拉开差距的关键 — 很多队伍能 Break 但 Fix 失败
- 部分比赛 Break 和 Fix 是独立计分的，即使 Break 没做出来也可以尝试 Fix（根据题目描述猜测漏洞点）

## 四、比赛流程（时间线）

```
比赛开始
  │
  ├─ 1. 下载题目附件（源码/二进制文件）
  │
  ├─ 2. 快速审计代码，定位漏洞
  │
  ├─ 3. Break：编写 exp 攻击靶机，获取 flag 并提交
  │
  ├─ 4. Fix：修复漏洞，打包上传
  │     ├─ Web：修改源码文件 → tar.gz 打包 → 上传
  │     └─ Pwn：patch 二进制 → tar.gz 打包 → 上传
  │
  ├─ 5. 平台自动 check（通常几分钟出结果）
  │     ├─ 通过 → 获得 Fix 分
  │     └─ 失败 → 可以重新修改再提交（通常不限次数）
  │
  └─ 6. 重复 2-5，处理下一道题
比赛结束
```

## 五、Fix 提交打包方法

这是很多新手容易踩坑的地方，**打包格式必须正确**。

### Web 题打包

```bash
# 假设题目给你的是一个 src/ 目录
# 你修改了 src/index.php 和 src/config.php

# 进入源码目录
cd src/

# 打包（注意：打包的是目录内的文件，不是目录本身）
tar -czvf ../fix.tar.gz ./*

# 或者只打包你修改的文件
tar -czvf ../fix.tar.gz index.php config.php
```

### Pwn 题打包

```bash
# 假设二进制文件名为 pwn1
tar -czvf fix.tar.gz pwn1
```

### 关键注意事项
1. **不要改变目录结构** — 打包后解压出来的路径必须和原始一致
2. **不要包含多余文件** — 只打包修改过的文件
3. **文件名必须一致** — 不能改文件名
4. **编码格式** — 保持和原文件一致（UTF-8）
5. **换行符** — Linux 环境用 LF，不要用 Windows 的 CRLF

## 六、平台操作要点

1. **仔细阅读比赛公告** — 每个比赛的具体规则可能不同
2. **注意提交次数限制** — 有些比赛限制 Fix 提交次数
3. **注意 flag 有效期** — 有些比赛 flag 会定期刷新
4. **靶机地址** — Break 时需要连接的靶机 IP 和端口，通常在平台上可以看到
5. **VPN** — 线下赛通常需要连接比赛 VPN 才能访问靶机
